# הכדורגל שלנו

אתר React בעברית: הרשמה ל־20 שחקנים, רשימת המתנה לפי סדר, 4 קבוצות של 5, ורמות פרטיות למנהלים.

## שימוש
השחקן שומר שם מלא ונרשם למשחק שהמנהל פתח. ביטול מקדם אוטומטית את הבא בהמתנה. ביטול עצמי נעשה מאותו מכשיר ודפדפן. המנהל יכול לבטל עבור כל שחקן או לשחרר חיבור מכשיר במאגר.

לניהול: ״כניסת מנהל״, שם המשתמש של הבעלים `admin`, והסיסמה שנמסרה בנפרד. הסיסמה אינה בקוד. במאגר אפשר לדרג 1–3, והבעלים יכול ליצור חשבונות מנהלים נוספים עם סיסמאות נפרדות.

חלוקה דורשת 20 שחקנים מדורגים. לכל רמה, הפרש הכמויות בין הקבוצות הוא לכל היותר 1. מבין חלוקות אלה נבחר הפרש הסכומים הנמוך ביותר. שינוי הרכב או רמה מבטל חלוקה קודמת.

## פיתוח
Node.js 22.18+:
```
npm ci
npm test
npm run build
npm run dev
```
`src/` מכיל את קוד הממשק; `index.html` ו־`assets/` הם תוצרי הבנייה הנשמרים עבור GitHub Pages מהשורש של main. לאחר כל שינוי בממשק יש לבנות ולשמור גם את התוצרים.

`supabase/functions/football-api/` מכיל את השרת. הנתונים נשמרים בשורה מוגנת בטבלת `football_club`. טבלאות הגרסה הישנה נשמרו כגיבוי ואינן משמשות את הגרסה החדשה.

RLS מופעל והגישה הישירה חסומה ל־anon/authenticated. השרת משתמש במפתח service-role המובנה בסביבת Supabase בלבד, ומחזיר לציבור רק שמות, רשימות וקבוצות. הרמות, פרטי המנהלים ואסימוני המכשירים אינם מוחזרים לשחקנים.

סיסמאות נשמרות כ־PBKDF2-SHA256 עם מלח אקראי ו־600,000 איטרציות. אסימוני ניהול פגים לאחר 12 שעות, נשמרים בדפדפן ב־sessionStorage ובמסד כגיבוב. קיימת הגבלת ניסיונות כניסה. שחקנים מזוהים באמצעות אסימון מכשיר אקראי, ללא אימות טלפון/דוא״ל.

שינויים מתבצעים עם בדיקת גרסה למניעת דריסת הרשמות מקבילות. משחקים קודמים נשמרים ב־history אך אין כרגע ממשק ארכיון.

הבדיקות כוללות את כל 231 הרכבי הרמות, סדר המתנה, מניעת כפילויות, פרטיות, הרשאות, ביטול מנהל והגבלת ניסיונות כניסה.

## תשלומים ופרסום קבוצות
המנהל מגדיר מחיר וקישור HTTPS לביט בלשונית תשלומים. אישור תשלום הוא סימון ידני בלבד, ללא אימות מול ביט וללא החזר אוטומטי. סימוני תשלום פרטיים למנהלים; תשלום של שחקן שביטל נשמר ומסומן לבדיקת החזר. משחק חדש מתחיל ללא סימוני תשלום. הרשמה אינה חסומה אוטומטית עד אישור תשלום.

חלוקה והחלפה בין שני שחקנים מקבוצות שונות נשמרות כטיוטה פרטית למנהלים. לחיצה על פרסום קבוצות מציגה אותן לכולם. החלפה, חלוקה חדשה או שינוי משתתפים/רמות מסתירים את הקבוצות עד לפרסום חוזר. כפתור שיתוף מכין הודעה עם פרטי המשחק, המחיר וקישור הביט; המשתמש בוחר נמען ושולח בוואטסאפ.

## קבוצות נפרדות — גרסת ניסיון
`?new=1` פותח הרשמת מארגן באימייל וסיסמה (10 תווים לפחות). קבוצה אחת לכל אימייל. לאחר הרשמה מתקבל `?group=<uuid>`, קישור קבוע להרשמה של חברים ולניהול. ניתן להיכנס שוב דרך "כבר נרשמתי" באותו עמוד. אין בגרסה זו אימות אימייל או שחזור סיסמה; מגבלה זו מוצגת בהרשמה.

הנתיב ללא פרמטר או `?group=asaf` ממשיך לנתונים המקוריים בטבלת football_club. קבוצות חדשות משתמשות בשורה נפרדת בטבלת football_groups, עם אותו מנגנון CAS לפי revision. כל בקשה בוחרת קבוצה אחת בלבד, סשן ניהול נבדק רק בתוך אותה קבוצה ואסימון מכשיר נגזר בנפרד לכל קבוצה. הנתונים הציבוריים בקישור כוללים שמות נרשמים, משחק וקבוצות שפורסמו; הקישור אינו סיסמת כניסה לשחקנים. דירוגים, תשלומים וסשנים אינם חשופים לציבור. אין ספריית קבוצות ציבורית. טבלאות הקבוצות ומגבלות ההרשמה חסומות ישירות ל-anon/authenticated.

המגרש והכתובת הם שדה טקסט חופשי. פריסת מסד הנתונים לקבוצות: supabase/groups.sql. בדיקות קבוצות מבודדות נמצאות ב-tests/groups.test.mjs.
